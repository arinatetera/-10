# ЛР2. Текст сообщения и нужный контакт

Вариант: **Notification**.

## Что дано

Обычная отправка работает, но модель пока принимает пустой текст, а сервис может попытаться отправить сообщение через канал, для которого у получателя нет контакта.

## Задание

### Шаг 1. Защитите текст `Notification`

При создании сохраняйте `message.strip()`. Если после удаления пробелов строка пуста, вызывайте `DomainError("INVALID_MESSAGE")`. Эта проверка должна работать при прямом создании `Notification`, без API.

### Шаг 2. Проверяйте контакт выбранного канала

Перед отправкой используйте готовую функцию `contact()`. Канал `EMAIL` требует непустой `email`, `SMS` — непустой `phone`. Получатель только с телефоном является корректным получателем SMS и не обязан иметь email.

Неизвестный канал вызывает `UNSUPPORTED_CHANNEL`.

### Шаг 3. Не записывайте неуспешную отправку

Проверка канала и контакта должна завершиться до добавления квитанции в журнал. При `INVALID_MESSAGE`, `MISSING_CONTACT`, `UNSUPPORTED_CHANNEL` или другой ошибке количество отправок не меняется.

## Примеры и границы

- `"   "` даёт `INVALID_MESSAGE`, `" OK "` сохраняется как `"OK"`.
- Получатель только с телефоном успешно получает SMS; EMAIL для него даёт `MISSING_CONTACT`.
- Неизвестный канал отклоняется.
- После любой ошибки новая запись в журнале не появляется.
